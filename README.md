# Эмулятор UNIX-оболочки — вариант №25

Практическая работа №1 по дисциплине **«Конфигурационное управление»**
(ИКБО-11-25, РТУ МИРЭА). Реализованы **все пять этапов** варианта 25
из сборника заданий, страницы 80–82.

Приложение работает как небольшая UNIX-подобная оболочка в окне Tkinter.
Исходная файловая система (VFS) читается из обычной папки **один раз**,
а дальнейшие операции выполняются **исключительно в оперативной памяти**.
Команда `mkdir` не меняет содержимое папки на диске.

## Требования

- Python 3.10 или новее (включая модуль `tkinter` для GUI).
- Сторонние библиотеки не требуются.
- ОС: Windows, Linux или macOS; скрипты `.sh` предназначены для POSIX.
- Для запуска графического окна нужна графическая среда.

На Linux, если Tkinter не установлен, установите системный пакет
`python3-tk`. Для автоматической проверки без GUI добавлен режим `--headless`.

## Запуск

Из корня проекта на **Windows**:

```bat
run.bat --vfs examples/vfs/deep
```

На **Linux / macOS**:

```sh
./run.sh --vfs examples/vfs/deep
```

Из любой ОС можно запустить напрямую:

```sh
python -m src.main --vfs examples/vfs/deep
```

По умолчанию загружается `examples/vfs/minimal`. Заголовок окна
создаётся из настоящих имени пользователя и имени компьютера:
`Эмулятор - [username@hostname]`. Внизу окна находится поле ввода,
сверху — журнал введённых команд, вывода и ошибок.

### Аргументы командной строки

| Аргумент | Значение |
| --- | --- |
| `--vfs ПАПКА` | Путь к каталогу — физическому источнику VFS |
| `--script ФАЙЛ` | Необязательный текстовый стартовый скрипт UTF-8 |
| `--headless` | Дополнительный терминальный режим для проверок |
| `--help` | Справка argparse |

При запуске отображаются параметры `vfs_path` и `script_path`.
Внутри эмулятора эти же настройки выводит команда `conf-dump`.

Пример запуска со стартовым скриптом:

```sh
python -m src.main --vfs examples/vfs/deep \
    --script examples/startup/all_commands.txt
```

Для проверки в терминале без графического экрана:

```sh
python -m src.main --headless --vfs examples/vfs/deep \
    --script examples/startup/all_commands.txt
```

В Windows PowerShell однострочная команда:

```powershell
py -3 -m src.main --headless --vfs examples/vfs/deep --script examples/startup/all_commands.txt
```

## Команды эмулятора

| Команда | Описание | Пример |
| --- | --- | --- |
| `ls [путь]` | Список файлов и папок VFS, отсортированный по имени | `ls /projects` |
| `cd [путь]` | Смена текущей папки VFS; без аргументов — в `/` | `cd projects/python` |
| `cal` | Календарь текущего месяца | `cal` |
| `cal ГОД` | Календарь заданного года | `cal 2026` |
| `cal МЕСЯЦ ГОД` | Календарь заданного месяца | `cal 10 2026` |
| `whoami` | Имя текущего пользователя реальной ОС | `whoami` |
| `mkdir ПУТЬ` | Создать одну папку в **памяти**, без `-p` | `mkdir reports` |
| `conf-dump` | Показать параметры запуска в формате ключ=значение | `conf-dump` |
| `exit` | Завершить работу эмулятора | `exit` |

Парсер **делит строку по пробельным символам**, как требует вариант 25.
Кавычки и пробелы внутри имён путей не поддерживаются. Оболочка не
запускает команды реальной ОС. Пути внутри VFS имеют UNIX-формат `/`.
`cd ..` работает, но выше виртуального `/` перейти невозможно.
Символические ссылки при чтении физической папки пропускаются.

Файлы копируются в память как байты. В базовом варианте просмотр их
содержимого не предусмотрен: необходимые команды — `ls`, `cd`, `cal`,
`whoami`, `mkdir`.

## Примеры интерактивной работы

```text
/ $ ls
projects
/ $ cd projects/python
/projects/python $ ls
src
tests
/projects/python $ mkdir reports
/projects/python $ ls
reports
src
tests
/projects/python $ cd reports
/projects/python/reports $ mkdir final
/projects/python/reports $ ls
final
/projects/python/reports $ whoami
<имя пользователя вашей ОС>
/projects/python/reports $ conf-dump
vfs_path=<абсолютный путь к примерам>/examples/vfs/deep
script_path=(нет)
```

**Ошибки** (эмулятор продолжает работать в интерактивном режиме):

```text
/ $ unknown
Ошибка: неизвестная команда: unknown
/ $ cd no-such-folder
Ошибка: cd: Путь не найден: /no-such-folder
/ $ mkdir projects
Ошибка: mkdir: такой файл или каталог уже есть
/ $ cal 13 2026
Ошибка: cal: ожидается cal [год] или cal [месяц] [год]
```

Ошибочная команда в **стартовом скрипте** останавливает исполнение этого
скрипта на первой ошибке. GUI остаётся открытым для дальнейшего ввода.
В режиме `--headless` процесс возвращает код `1` для ошибки скрипта
и `2` для ошибки загрузки VFS.

## Проверка всех пяти этапов

### Этап 1 — REPL

Графическое окно Tkinter, заголовок с данными ОС, простой парсер,
заглушки `ls` и `cd` на этом историческом этапе, команды `exit` и
обработка ошибок. Состояние доступно в **первом Git-коммите**.

### Этап 2 — конфигурация

Добавлены `--vfs`, `--script`, вывод параметров при запуске и по
`conf-dump`, показ введённых команд и результатов стартового скрипта.
Исполнение останавливается на первой ошибке. Состояние — второй коммит.

### Этап 3 — VFS

Добавлена рекурсивная загрузка папки в память, три вида тестовой VFS:
`minimal`, `files`, `deep`. Вложенность в `deep` — более трёх уровней.
Состояние — третий коммит.

### Этап 4 — основные команды

Реализованы `ls`, `cd`, `cal`, `whoami`. Примеры успешного выполнения
и ошибок в `examples/startup/commands*.txt`. Состояние — четвёртый коммит.

### Этап 5 — дополнительная команда

Реализована `mkdir` с проверкой аргументов и отсутствия родителя или
совпадающего имени. Новые каталоги хранятся только в памяти. Состояние —
пятый коммит.

python -m unittest discover -s tests -v

./scripts/check_config.sh
./scripts/check_vfs.sh
./scripts/check_commands.sh
./scripts/check_mkdir.sh
./scripts/check_errors.sh

```sh

    --script examples/startup/all_commands.txt
```

## Git и требования оформления

- Репозиторий **публичный**; `README.md`, `.gitignore`, `src/`, `tests/`,
  `run.sh` и `run.bat` находятся в корне.
- Используются Conventional/Scoped Commits:
  `feat(repl): ...`, `feat(config): ...`, `feat(vfs): ...`.
- В Git не добавляются `__pycache__`, `*.pyc`, IDE-настройки, бинарники,
  `.venv`, артефакты сборки и архивы.
- Исходный код документирован docstring, функции короткие; для Python
  принят лимит 80 символов на строку.
- История репозитория содержит пять отдельных коммитов по этапам.

Инструкция по публикации — в `GITHUB.md`.
